# Update Itixo models

Use the source checkout. Never edit an installed plugin cache or hand-edit generated agent files. Edit only Copilot catalog entries: `aliases.<alias>.providers.copilot` and `providers.copilot.models`. Never edit another provider's entries.

1. Honor a user-specified checkout. Otherwise use the current checkout only when it contains `CLAUDE.md`, `base/rules/agents.md`, `base/agents/`, `plugins/copilot/itixo`, and `scripts/generate-agents.js`. Verify its Git root and `origin` or `upstream` points to `ITIXO/itixo-marketplace` or a fork the user authorized. Reject caches and distribution copies. If multiple valid checkouts remain or no source checkout exists, ask which path to use.
2. Read source `AGENTS.md` when present, `CLAUDE.md`, `base/rules/agents.md`, `plugins/copilot/itixo/rules/agents.md`, the catalog at `base/models/model-catalog.json`, and the generator. Use the `dirigent` skill for repository mapping and implementation, test, or documentation delegation only when Dirigent is already enabled in this chat; otherwise follow other applicable instructions. Keep the catalog as the model source of truth.
3. Before proposing or applying updates, present exactly two tables populated from the current source, not static examples:
   - **Level | Current model | Possible options**: include the Copilot cheap, mid, security, and orchestrator levels. Resolve each current tier alias through `providers.copilot.models` and `aliases.<alias>.providers.copilot.default`; show the alias and concrete version. List every alias with a Copilot entry and its `versions`, marking its default. Keep pinned selectors available for explicit compatibility requests. Show orchestrator as user-selected/inherit when its assignment is `inherit` or absent; do not invent a tier default or change the running session model.
   - **Agent name | Level**: include all eight canonical agents using the agent-to-tier mapping in `base/rules/agents.md`, including `itixo-planner` as orchestrator. Note any known explicit per-agent model or effort overrides beside the agent name; do not hide them behind a tier default.
4. Use a questionnaire tool when available; otherwise ask the same choices in text. Collect the level to change, its alias, and the concrete version for each selected alias. Ask once per distinct alias and reuse that version across its selected levels. Include keeping current values as an option. Honor choices already supplied without asking again; never infer choices from a recommendation or alias name. For a model not yet in the catalog, verify support before presenting it as an option. For a verify/check request, the tables remain read-only.
5. Preserve existing custom choices and every non-Copilot entry. Treat `providers.copilot.models` as tier-to-alias assignments and `aliases.<name>.providers.copilot` as the Copilot version catalog. A Copilot entry is the only availability signal; never infer support from an alias name or another provider. A request may independently change a tier assignment and/or an alias's Copilot `default` or `versions` entry; do not require both changes. Verify each requested model's exact Copilot ID against current official Copilot documentation. For Copilot model discovery, the [gh-aw model alias table](https://github.github.com/gh-aw/reference/model-tables/#model-aliases) documents aliases resolved at compile time from ordered provider-scoped glob patterns, including `sonnet` patterns `copilot/*sonnet*` and `anthropic/*sonnet*`; treat these as discovery hints only, not native Copilot selectors or proof of availability. Verify the exact native Copilot model ID against official Copilot documentation before adding it to the catalog or generated agents. Ask only when tier or replacement policy is missing.
6. For a verify or check request, make no edits: report the proposed catalog diff or that no change is needed, plus validation evidence. For an update or promote request, edit the catalog in the source checkout, update defaults only within the authorized tier policy, regenerate with `node scripts/generate-agents.js`, and update affected user-facing docs, versions, and changelogs.
7. For an update, run `node scripts/generate-agents.js --check`, `node --test tests/*.test.js`, `node tests/validate.js`, and `node scripts/validate-plugin-changes.js --base <resolved-merge-base> --changelog-dir .`. Resolve `<resolved-merge-base>` from the current branch and `origin/HEAD`; report a missing or unusable base instead of weakening the check. Inspect `git diff` and `git status`.
8. For an update, commit each meaningful unit with `caveman:caveman-commit` or a terse Conventional Commit. Create or update a reviewable PR only when the user explicitly authorized publishing, using the configured GitHub connector or MCP first. Do not merge, release, or mutate external systems implicitly.

After release, users get new models by updating the Copilot plugin through `copilot plugin update` or their normal plugin flow. Copilot has no installer; source verification alone never changes installed agents.
